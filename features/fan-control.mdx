Pyren controls laptop fans via the `hp-wmi` kernel module and supports four distinct fan modes. Two of these modes (`auto` and `max`) require only the `pwm1_enable` sysfs file, which is available even on boards the stock driver has limited support for. The other two (`manual` and `curve`) additionally require `pwm1`, which lets a specific speed be commanded. Before offering manual or curve controls, Pyren reads `capabilities` from the daemon to confirm what the running driver actually exposes on this machine — rather than discovering missing support from a failed write.

<Note>
Fan mode is completely independent of power profile. You can run `manual` or `curve` in Eco, Balanced, Performance, or Unlimited. Changing the power profile never writes to the fan module, and changing the fan mode never writes to the power envelope.
</Note>

## Fan modes

| Mode | Description |
|---|---|
| **Auto** | Hands the fans back to the firmware's own temperature-to-RPM curve for the active power profile. Each profile has its own EC curve; Eco makes fans start later and at lower speeds, not merely spin slower. |
| **Max** | Drives fans to the maximum configured RPM. |
| **Manual** | User sets a fixed fan speed (0–100%) that holds constant, regardless of temperature. |
| **Curve** | User defines a custom temperature/speed curve. The daemon interpolates between points and follows the curve in real time. |

Each power profile stores its own fan curve. When you switch from Eco to Performance, the fan module automatically picks up that profile's stored curve. The `fan` and `power` modules communicate through the daemon's internal event bus — neither module calls the other directly.

## Lower minimum fan speed

The stock `hp-wmi` driver enforces a minimum fan speed floor — the slowest entry in its own fan table — and clamps every manual speed to it. On the HP OMEN (board 8D2F), this floor is 1800 RPM.

Pyren's patched driver adds a `min_rpm_override` module parameter, which lifts that clamp. After calibration, Pyren measured a stable minimum of 600 RPM on the 8D2F, and uses 700 RPM (one 100 RPM step above the measured floor) as its effective minimum. Below that floor the firmware takes control and stops the fans when the machine is cool.

<Steps>

### Run calibration

`fan.calibrate` spins the fans to max, watches the tachometer until the reading settles, then returns them to the previous mode. The same call measures the stable minimum — how slow the fans can hold without stalling.

### Choose a floor

`keepDriverFloor` (on by default) lets you keep the stock driver's conservative floor or use Pyren's measured lower one. Switch it off to allow Pyren's floor via Settings.

### The daemon pins the ceiling to the driver

The measured max RPM is written to `/etc/modprobe.d/pyren-hp-wmi.conf` so the driver uses the right ceiling on every load — not just while the daemon is running.

</Steps>

### Automatic stall correction

While Pyren's lower floor is active, the daemon watches the tachometer on every control tick. If a commanded low speed reads near zero, or jumps back up (a stalled fan restarting itself), that counts as a fault. After three faults within half an hour, the daemon automatically raises the stored minimum by one 100 RPM step, updates the driver's `min_rpm_override`, and logs the event to `floorNotices`. Each correction is shown in the app's notification history and fires an OS notification.

The automatic correction only ever raises the floor — never above the driver's own floor — and waits at least five minutes between raises. A full recalibration clears the log and remeasures from scratch.

## Per-fan RPM readout

On machines with two fans, Pyren reads both tachometers separately and labels them:

| Sensor | Label |
|---|---|
| `fan1_input` | CPU fan |
| `fan2_input` | GPU fan |

Per-fan readout is on by default and can be toggled in Settings. It is automatically hidden on single-fan machines.

## Fan cleaning mode

The fan cleaner spins the fans **in reverse** to help dislodge accumulated dust. It uses HP's `SECU` buffer protocol over `/proc/acpi/call` (the same path used by the lightbar), and requires the `acpi_call` kernel module to be loaded.

<Warning>
While a cleaning cycle is running, the machine has **no working cooling**. The daemon enforces a hard maximum temperature of 70 °C before a cycle can be started. Do not run fan cleaning under sustained load. The timeout is enforced by three independent watchdog mechanisms. Stopping the cycle is always safe — `stopCleaning` is idempotent.
</Warning>

The cleaner supports two firmware generations:

- **Modern ("CleanCreek")** — per-fan speed in hundreds of RPM, with a controlled ramp up into reverse and a ramp back down to stop.
- **Legacy** — a single toggle bit; no speed control and no ramp.

Which generation a machine uses is probed automatically, never guessed from the model name.

## CLI usage

```sh
# Read current fan status
pyren-ctl fan get

# Switch to auto mode (firmware curve)
pyren-ctl fan set auto

# Set manual speed at 50%
pyren-ctl fan set manual 50

# Apply a custom temperature/speed curve
# Format: tempC:percent,tempC:percent,...
pyren-ctl fan curve 40:20,60:50,85:100

# Run calibration (blocks while fans spin)
pyren-ctl fan calibrate

# Fan cleaning
pyren-ctl fan clean
pyren-ctl fan clean-stop
```

Pyren's system monitor reads `/proc`, `/sys`, and DRM `fdinfo` — it has no dependency on HP-specific hardware. All metrics are available on any Linux machine, which also means the monitor UI can be developed and tested without an OMEN laptop present. The daemon keeps the previous sample to compute deltas, and the sampler is primed at construction so the very first call returns real numbers rather than zeros.

## GPU details

Pyren identifies GPUs by PCI slot. Integrated GPUs hang off the root bus (`0000:00:…`); a discrete card sits behind a PCIe bridge. On hybrid laptops both appear labeled separately.

Intel iGPU utilization is read via the i915 perf PMU.

<Info>
Intel iGPU utilization requires `CAP_PERFMON`, which the daemon has when running as root (the normal production configuration). Without it, the iGPU usage field is `null` — which means "we were not permitted to ask," not "this GPU is idle." `system.getInfo`'s `privileges.perfEvents` field tells you whether the i915 PMU opened successfully.
</Info>

NVIDIA GPU metrics come from `nvidia-smi`. For AMD and other drivers, Pyren reads `gpu_busy_percent`, `mem_info_vram_*`, and `gt_act_freq_mhz` (or the Intel GT tile path) directly from DRM sysfs. Fields a driver does not expose are reported as `null`.

## Process GPU accounting

Per-process GPU percentage comes from the kernel's DRM `fdinfo` interface (`/proc/<pid>/fdinfo/<fd>`, `drm-engine-*` keys) — the same source used by `nvtop`. This covers `i915`, `xe`, and `amdgpu`.

<Note>
`gpuPercent: null` for a process means the driver **does not expose per-client GPU accounting** for that process — this is normal for NVIDIA's proprietary driver. It does not mean the process is idle. The UI draws `null` and a zero percentage differently so you can tell them apart.
</Note>

Two subtleties the implementation handles: multiple file descriptors can reference the same `drm-client-id` (each reporting that client's whole counter, not a fraction), and an engine can have multiple instances with shared nanoseconds.

## Advanced mode

Enabling Advanced mode in Settings adds:

- **Per-core CPU graphs** — a small time-series graph for each physical core's usage and clock.
- **Per-GPU detail** — expanded VRAM, power, and clock breakdown per card.
- **Detailed RAM analysis** — breakdown of cached, buffered, and mapped memory usage.

## Temperature units

All temperatures are displayed in either **Celsius** or **Fahrenheit**, switchable in Settings. The unit preference applies everywhere temperatures appear in the app — the system monitor, the fan curve editor, and the automatic-switching thresholds.
